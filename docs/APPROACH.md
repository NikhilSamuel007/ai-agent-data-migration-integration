# Relay: controlled autonomy for client migration

**Problem and scope.** A Python agent turns heterogeneous employee CSV/XLSX exports into one validated dataset and delivers it to a mock HTTP API. React/TypeScript gives the consultant source profiles, mapping evidence, a focused review queue, delivery outcomes, and an audit. The versioned employee schema separates HR lifecycle status from optional login account status.

**Architecture.** FastAPI controllers delegate to ingestion, pandas profiling, evidence-based mapping, deterministic normalization/validation, reconciliation, and a target client. SQLite preserves runs and audit history. The model boundary is swappable: Ollama/Qwen supplies structured proposals while local MiniLM ranks semantic candidates. Pydantic validates model and API output contracts. There is no swarm or chatbot.

**Autonomy boundary.** Unique explicit aliases proceed automatically, with values validated separately. Whitespace, email casing, and dates with only one valid interpretation are normalized. Exact normalized duplicates are excluded with source lineage retained. Shared identities with conflicting values, missing required fields, and ambiguous dates require review. Validation runs before and after cleanup; human corrections undergo the same checks. The agent never guesses missing facts, title-cases names arbitrarily, or overwrites existing target records.

**Evidence, not magic confidence.** Unfamiliar mappings combine semantic similarity, LLM agreement/self-score, and profile compatibility. Automatic acceptance requires every gate: policy score ≥0.90, semantic similarity ≥0.80, top-two margin ≥0.20, value compatibility ≥0.95, agreeing LLM score ≥0.90, at least three values, no competing target, and no explicitly ambiguous header. These are conservative heuristic thresholds, not calibrated probabilities; each evidence source is counted once. Missing/invalid model output forces review. The real-model evaluation script records proposals and safe automation coverage on 14 authored cases; this is a regression check, not statistical calibration. Runtime outcomes and limitations are recorded separately in VERIFICATION.md.

**Recovery and human control.** Resolving the final review resumes delivery automatically. Transient API failures get at most three attempts with bounded backoff, each audited. Permanent conflicts and exhausted retries escalate. Stable run/record identities prevent duplicate writes after timeouts or restarts. Rollback removes only this run's target inserts and preserves the audit. The demo shows safe cleanup, a human Status mapping decision, automatic recovery, exhausted retry followed by consultant retry, and rollback.

**Delta and next steps.** The value beyond AI output is the operational contract: provenance, measurable profiles, evidence gates, mandatory revalidation, exact-versus-conflicting identity handling, idempotency, bounded retries, and ownership-scoped rollback. Next, calibrate mapping thresholds on labeled client exports, add approved locale policies and historical schema migrations, then authenticated reviewers, retention controls, a durable outbox, and real connectors. Keep ambiguous or potentially destructive decisions with humans.
